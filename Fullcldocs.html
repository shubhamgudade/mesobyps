⬡ ProxyBin — Rotating Proxy API

Base URL: https://proxybin.netlify.app/api/proxy

High-speed HTTP/HTTPS request forwarder through localized rotating IP nodes with sticky session support.

POST https://proxybin.netlify.app/api/proxy
Use Case

Sends a synchronous or streamed HTTP request through an ephemeral rotating proxy IP node.

Request Body Fields
FieldTypeRequiredDescription
urlstring✅Target destination URL (https only)
methodstring❌HTTP verb: GET POST PUT PATCH DELETE HEAD
headersobject❌Extra HTTP request headers to forward to target
bodystring|object❌Raw payload body (JSON string, encoded data, or text)
bodyIsBase64bool❌Set to true if payload body is base64 encoded
proxy_countrystring❌Exit node country code (default: random geo-rotation)
retriesint❌Max attempts with fresh IP nodes (max: 8, default: 4)
streambool❌Pipe response live (SSE / long-poll)
stickybool❌Keep same IP across requests; returns direct_url
direct_urlstring❌Reuse dedicated node from previous sticky call
Response Schema
{
  "status": 200,
  "statusText": "OK",
  "headers": { "content-type": "application/json" },
  "data": {},
  "data_b64": "...",
  "binary": false,
  "size": 1234,
  "proxyCountry": "sg",
  "attempt": 1,
  "success": true,
  "elapsed_ms": 1857,
  "elapsed_sec": 1.857
}

Geo-Location Routing — Available Country Codes

🇺🇸 us — United States 🇵🇱 pl — Poland 🇸🇬 sg — Singapore 🇩🇪 de — Germany 🇫🇷 fr — France 🇳🇱 nl — Netherlands 🇬🇧 gb — Great Britain 🇨🇦 ca — Canada
APAC Tip: Use proxy_country: "sg" for lowest latency to Meesho's Indian servers. Set retries: 1 to avoid retry cascade overhead.

ProxyBin — Example: Sticky Session Workflow

# Step 1: Initialize sticky session node
RESP=$(curl -s -X POST https://proxybin.netlify.app/api/proxy \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://target.com/login",
    "method": "POST",
    "sticky": true
  }')
DIRECT=$(echo $RESP | jq -r '.direct_url')

# Step 2: Reuse same node
curl -s -X POST https://proxybin.netlify.app/api/proxy \
  -H "Content-Type: application/json" \
  -d "{\"url\": \"https://target.com/dashboard\", \"method\": \"GET\", \"direct_url\": \"$DIRECT\"}"

Every request to prod.meeshoapi.com requires these headers:

authorization: 32c4d8137cn9eb493a1921f203173080
meesho-user-context: anonymous  (or "logged_in" after auth)
application-id: com.meesho.supplz
app-version: 29.3
app-version-code: 864
app-client-id: android
app-sdk-version: 36
country-iso: in
instance-id: [UUIDv4 without hyphens]
app-session-id: [UUIDv4 with hyphens]
app-user-id: [Integer user ID — post login]
u-token: [Base64 encoded phone param — post login]
app-user-location: [Base64 JSON: {lat, long, city, pincode}]
shield-session-id: [UUID anti-fraud token]
xo: [Composite Base64 JWT Token]
Content-Type: application/json; charset=UTF-8
Accept-Encoding: gzip
User-Agent: okhttp/4.9.0
xo header: Composite JWT bundling anonymous_user_id (or registered user_id), instance_id, and expiration timestamps. Refreshed on every Meesho login response as xoox.xo.
